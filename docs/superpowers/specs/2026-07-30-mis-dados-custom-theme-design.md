# "Mis Dados" Custom Dice Theme — Design

## Problem

The user photographed their own physical dice set (glossy black
resin with an embedded skull sculpt and gold numerals) and wants it
represented as a dice-box theme, continuing an earlier brainstorm
where the general approach (material match, one set to start, photos
delivered via local file path) was already agreed. This design covers
the first concrete implementation of that idea, now with real source
photos in hand.

## Key Finding: `standard` vs `color` Material Types

The existing Rock/Rust/Steel/Mist themes all use
`material.type: "color"` — a single `themeColor` tints a shared base
texture at runtime. That doesn't work here: this die needs **two**
colors (a black body and gold numerals), and a single tint can't
produce two different final colors from one source image.

Investigating the actual texture files revealed the fix: themes with
`material.type: "standard"` (Wooden, BlueGreenMetal, GemstoneMarble)
use a **baked, final-color diffuse texture** with no runtime tinting.
Critically, this texture is a real UV atlas — every die face's number
glyph is painted directly into the image at a fixed position, not
generated by the mesh. All `smoothDice`-mesh themes (Wooden, Rock,
Rust, Steel, Mist) share the **exact same atlas layout** (same face
shapes/positions), just with a different background image baked in.

This means a custom `standard` theme can be built by taking an
existing atlas as a positional template, recoloring it, and
compositing new imagery onto specific face regions — all via image
editing, with no mesh authoring or code changes to `dice-box` itself.

## Roster Addition

**New category: "Mis Dados"** (its own group in the Ajustes picker,
separate from Normales/Especiales/Mistborn) — a home for this and any
future photographed physical sets.

- **Mis Dados** (`systemName: "misDados"`) — deep glossy black base
  (`#050505`), gold numerals (`#D4AF37`), with a skull texture
  (cropped/blended from the source photos) composited onto all 6 d6
  faces plus 2 larger d20/d12 faces. Confirmed via live 3D renders
  during design, including verifying the skull is visible and the
  numeral stays legible when that face is actually rolled.

## Asset Pipeline (already prototyped and validated)

1. Take Rock's `diffuse-light.png` (512×512 atlas) as the positional
   template.
2. Flatten transparency to black, then apply a black→gold color
   lookup table (`magick ... -clut`) to recolor the background to
   `#050505` and numerals to `#D4AF37` in one pass, producing a
   full-color (non-grayscale) result.
3. Crop clean bone-texture patches from the source photos (avoiding
   the gold numeral regions in the originals), and composite them
   onto 8 target face regions using `-compose Lighten`, which keeps
   whichever pixel (skull texture or gold numeral) is brighter at
   each point — so the recolored gold numerals stay legible on top of
   the skull texture without a separate masking step.
4. Save the result as `diffuse.jpg`.
5. Reuse Rock's `normal.png` and `specularity.jpg` as-is (surface
   relief/shine, unaffected by the color rework) and Rock's
   `smoothDice.json` mesh file.
6. New `theme.config.json`, `material.type: "standard"` (no
   `themeColor` — colors are baked in).

## Source Photos

The 5 HEIC originals (`dadosreales/` at repo root) are **not**
committed — they're working material, not something the running app
needs. Only the derived `diffuse.jpg` (plus the reused normal/specular
maps and the new config) ships in `public/assets/themes/misDados/`.

## Data Model Change

`DiceThemePreset.category` (`src/data/dice-themes.ts`) gains a fourth
value: `"normal" | "especial" | "mistborn" | "personal"`.
`DiceThemeId` gains `"misDados"`.

```typescript
{
  systemName: "misDados",
  label: "Mis Dados",
  category: "personal",
  swatch: "#050505",
}
```

No `themeColor` field — this preset doesn't use runtime tinting.

## UI Change

`DiceThemePickerModal.tsx` gains a fourth grouped section ("Mis
Dados"), filtering `DICE_THEMES` on `category === "personal"` — same
pattern as the existing three sections.

## Testing

Same scope as prior dice-theme work: no dedicated unit tests for the
static catalog entry or the asset files themselves. Manual
verification (already performed during design): open the picker,
confirm the "Mis Dados" section appears with the correct swatch,
select it, and roll dice until both a d6 face and the d20 face
carrying the skull patch are observed, confirming the texture renders
and the numeral stays legible.

## Out of Scope

- Extending skull coverage to every face of every die type (d4, d10,
  d100) — the current 8-face coverage (all d6 + 2 larger faces) was
  explicitly chosen as the target scope, confirmed against a live
  render.
- Any future additional physical sets — the "Mis Dados" category is
  structured to make adding a second entry later straightforward, but
  authoring that theme's assets is separate future work.
