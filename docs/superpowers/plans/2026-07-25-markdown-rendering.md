# Markdown Rendering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render `**bold**`-style markdown in 5etools-derived descriptions and user-authored Notes/Quests/Journal content, instead of showing literal asterisks.

**Architecture:** One shared `<Markdown>` component (`react-markdown` + `remark-gfm`) replaces raw `{description}`/`{content}` renders across full read-only display sites. A `stripMarkdown()` helper handles character-truncated or `line-clamp`ed previews, and single-line contexts like `CompactRow`'s `meta` span, where partial markdown syntax or block-level HTML would otherwise leak through or break nesting. Notes and Quests gain the same read-only "view" mode Journal already has, so markdown has a place to render (their cards currently jump straight into an edit textarea). A pre-existing bug in `scripts/extract-5etools.ts`'s tag-stripping regex (it doesn't handle nested `{@tag ...}` markup) gets fixed and the data re-extracted.

**Tech Stack:** Next.js 15 (static export) / React 19 / TypeScript / Tailwind CSS 4 / Vitest. New deps: `react-markdown` (^10.1.0), `remark-gfm` (^4.0.1).

## Global Constraints

- `npm run lint` must report 0 errors — it's the only check that catches React Hooks ordering violations; this plan doesn't touch hook order, but the standing bar still applies.

```typescript
// src/lib/markdown.ts
export function stripMarkdown(text: string): string {
  return text
    .replace(/\*\*(.+?)\*\*/g, "$1")
    .replace(/\*(.+?)\*/g, "$1")
    .replace(/^[-*+]\s+/gm, "")
    .replace(/^\d+\.\s+/gm, "");
}
```

### Task 2: `<Markdown>` component

**Files:**
- Modify: `package.json` (add `react-markdown`, `remark-gfm`)
- Create: `src/components/ui/Markdown.tsx`

**Interfaces:**
- Consumes: nothing from earlier tasks.
- Produces: `Markdown({ children, className }: { children: string; className?: string })` — a client component. `children` is the raw markdown string (not React nodes — this is a leaf renderer, always called as `<Markdown className="...">{someDescriptionString}</Markdown>`). `className` is applied to the wrapping `<div>` and cascades (font size, color) to the rendered markdown the same way it would to a plain `<p>`, since Tailwind's text-size/color utilities set inherited CSS properties. Every later task that needs a full read view imports this as `import { Markdown } from "@/components/ui/Markdown";`. `Markdown` always renders a block-level `<div>` — never use it inside a `<span>` or other phrasing-content-only element (truncated previews and `CompactRow`'s `meta` span use `stripMarkdown` instead, not `Markdown` — see Tasks 7, 10, 11).

- [ ] **Step 1: Install dependencies**

```bash
npm install react-markdown@^10.1.0 remark-gfm@^4.0.1
```

- [ ] **Step 2: Create the component**

```tsx
// src/components/ui/Markdown.tsx
"use client";

import ReactMarkdown from "react-markdown";
import remarkGfm from "remark-gfm";

export function Markdown({
  children,
  className,
}: {
  children: string;
  className?: string;
}) {
  return (
    <div className={className}>
      <ReactMarkdown
        remarkPlugins={[remarkGfm]}
        components={{
          p: ({ children }) => <p className="leading-relaxed">{children}</p>,
          strong: ({ children }) => (
            <strong className="font-semibold text-foreground">
              {children}
            </strong>
          ),
          em: ({ children }) => <em className="italic">{children}</em>,
          ul: ({ children }) => (
            <ul className="list-disc pl-4 space-y-0.5">{children}</ul>
          ),
          ol: ({ children }) => (
            <ol className="list-decimal pl-4 space-y-0.5">{children}</ol>
          ),
          li: ({ children }) => <li>{children}</li>,
        }}
      >
        {children}
      </ReactMarkdown>
    </div>
  );
}
```

### Task 8: Fix nested-tag stripping in the 5etools extractor and re-extract data

**Files:**
- Modify: `scripts/extract-5etools.ts:7-11` (the `stripMarkup` function), `:259-270` (`formatCastingTime`, inside `extractSpells`)
- Regenerate: `src/data/actions.ts`, `src/data/spells.ts` (and any other `src/data/*.ts` files the re-run touches)

**Context:** `src/data/actions.ts` line 37 and eight `castingTime` fields in `src/data/spells.ts` contain literal, un-stripped 5etools tags: `{@book stabilize a creature.}` and `{@variantrule Unarmed Strike|XPHB}`. Root cause, confirmed against the raw source (`../dnd/5etools-src/data/actions.json`): the Help action's raw text is a **nested** tag —
`{@note Additionally, the Help action may be used to {@book stabilize a creature|XPHB|1|Stabilizing a Character}.}` — and `stripMarkup`'s regex runs a single pass, so it can't correctly resolve one `{@...}` tag containing another. `castingTime` values separately never call `stripMarkup` at all — `formatCastingTime` builds the string directly from raw JSON fields.

**Interfaces:**
- Consumes: nothing from earlier tasks (independent of the `Markdown` component work).
- Produces: no new interface — this task fixes existing generated data that Tasks 3-7's call sites will render.

- [ ] **Step 1: Make `stripMarkup` iterate to a fixed point**

In `scripts/extract-5etools.ts`, replace:
```typescript
function stripMarkup(text: string): string {
  return text
    .replace(/\{@\w+\s+([^|}]+?)(?:\|[^}]*)?\}/g, "$1")
    .replace(/\{@dc\s+(\d+)\}/g, "DC $1");
}
```
with:
```typescript
function stripMarkup(text: string): string {
  let prev: string;
  do {
    prev = text;
    text = text
      .replace(/\{@\w+\s+([^|}]+?)(?:\|[^}]*)?\}/g, "$1")
      .replace(/\{@dc\s+(\d+)\}/g, "DC $1");
  } while (text !== prev);
  return text;
}
```
Looping until the string stops changing resolves nested tags: the first pass strips the innermost-resolvable tag boundaries it can match (which, for a tag containing another tag, leaves a malformed partial tag behind — verified: `{@note ... {@book stabilize a creature|XPHB|1|Stabilizing a Character}.}` becomes `... {@book stabilize a creature.}` after pass one), and the second pass cleans up what's left (`{@book stabilize a creature.}` → `stabilize a creature.`).
